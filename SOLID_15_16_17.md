# Principios SOLID — UC-15, UC-16 y UC-17: Práctica y Evaluación

Módulo: `practica_evaluacion` (dominio) / `practica_application_service` (aplicación).

Historias cubiertas:
- **UC-15** — Iniciar práctica a partir de una postulación.
- **UC-16** — Subir entregable de una práctica.
- **UC-17** — Ver historial de entregables de una práctica.

## 1. SRP — Single Responsibility Principle

**Idea:** cada clase debe tener una única razón para cambiar.

**Aplicación:** el flujo de las tres historias atraviesa cinco clases, cada una con una
responsabilidad exclusiva y una razón de cambio distinta.

| Clase | Responsabilidad única | Razón de cambio |
|---|---|---|
| `Practica` | Reglas de negocio del ciclo de vida de la práctica | Cambia si cambia una regla de negocio (ej. condiciones para finalizar) |
| `PracticaFabrica` | Construir una `Practica` válida (UC-15) | Cambia si cambian los requisitos para iniciar una práctica |
| `PracticaApplicationService` | Orquestar los casos de uso | Cambia la secuencia de pasos de un caso de uso |
| `SqlAlchemyPracticaRepository` | Persistencia en base de datos | Cambia el motor de BD o el ORM |
| `PracticaController` | Serialización HTTP | Cambia el formato de la respuesta JSON |

**Fragmento de código (UC-15):**

`domain/practica_evaluacion/practica_fabrica.py`, líneas 11-18
```python
def iniciar_practica(self, postulacion_id, practicante_id):
    if postulacion_id is None or practicante_id is None:
        raise ValueError("Se requiere postulación y practicante para iniciar la práctica")

    return Practica(
        postulacion_id=postulacion_id,
        practicante_id=practicante_id,
        estado=Practica.ESTADO_EN_CURSO,
    )
```
`PracticaFabrica` solo construye una `Practica` válida; no persiste, no valida HTTP, no
conoce postulaciones más allá de sus ids.

**Fragmento de código (UC-16/UC-17):**

`domain/practica_evaluacion/practica.py`, líneas 21-27 y 44-45
```python
def subir_entregable(self, archivo):
    if self.estado == self.ESTADO_FINALIZADA:
        raise ValueError("No se pueden subir entregables a una práctica finalizada")
    entregable = Entregable.crear(practica_id=self.id, archivo=archivo)
    self.entregables.append(entregable)
    return entregable

def obtener_historial_entregables(self):
    return sorted(self.entregables, key=lambda e: e.fecha_subida)
```
La regla de negocio (no subir entregables a una práctica finalizada, ordenar el historial)
vive únicamente en `Practica`; ni el controller ni el repositorio la conocen.


## 2. DIP — Dependency Inversion Principle

**Idea:** los módulos de alto nivel no deben depender de módulos de bajo nivel, sino de
abstracciones.

**Aplicación:** `PracticaApplicationService` (alto nivel) no importa SQLAlchemy ni conoce
ningún detalle de persistencia. Depende de repositorios recibidos por constructor, cuyo
contrato está definido por la abstracción `IPracticaRepository`.

**Fragmento de código:**

`application/practica_application_service.py`, líneas 9-14
```python
class PracticaApplicationService:
    def __init__(self, practica_repository=None, perfil_repository=None,
                 postulacion_repository=None, convocatoria_repository=None):
        self.practica_repository = practica_repository
        self.perfil_repository = perfil_repository
        self.postulacion_repository = postulacion_repository
        self.convocatoria_repository = convocatoria_repository
```

## 3. ISP — Interface Segregation Principle

**Idea:** los clientes no deben depender de métodos que no usan; preferir interfaces
pequeñas y específicas antes que una interfaz "gorda" genérica.

**Aplicación:** `IPracticaRepository` solo declara los 3 métodos que
`PracticaApplicationService` realmente necesita para las historias UC-15/16/17
(`save`, `find_by_id`, `find_by_practicante_id`). No es un repositorio genérico con
decenas de métodos de entregables/evaluaciones sueltos que cualquier implementación
estaría obligada a soportar aunque no los use; esas operaciones se resuelven a través
del propio agregado `Practica` (composición) en memoria.

**Fragmento de código:**

`domain/practica_evaluacion/i_practica_repository.py`, líneas 7-17 (contrato completo, solo 3 métodos)
```python
class IPracticaRepository(ABC):
    @abstractmethod
    def save(self, practica):
        pass

    @abstractmethod
    def find_by_id(self, practica_id):
        pass

    @abstractmethod
    def find_by_practicante_id(self, practicante_id):
        pass
```
Cualquier implementación futura solo debe satisfacer estos 3 métodos, no una interfaz sobrecargada de operaciones que no le conciernen.

## 4. LSP — Liskov Substitution Principle (bonus)

**Idea:** una subclase (o implementación concreta) debe poder sustituir a su abstracción
sin alterar el comportamiento esperado por quien la consume.

**Aplicación:** `SqlAlchemyPracticaRepository` implementa los 3 métodos abstractos de
`IPracticaRepository` respetando el mismo contrato: `save` recibe y devuelve una
`Practica` de dominio, `find_by_id` devuelve una `Practica` o `None`, y
`find_by_practicante_id` devuelve una lista (posiblemente vacía). En ningún caso lanza
`NotImplementedError` ni cambia el tipo de retorno esperado, por lo que
`PracticaApplicationService` puede usarlo de forma intercambiable con cualquier otra
implementación futura del mismo contrato.

**Fragmento de código:**

`infrastructure/sqlalchemy_practica_repository.py`, líneas 53-59
```python
def find_by_id(self, practica_id):
    model = db.session.get(PracticaModel, practica_id)
    return self._to_practica_domain(model)

def find_by_practicante_id(self, practicante_id):
    models = PracticaModel.query.filter_by(practicante_id=practicante_id).all()
    return [self._to_practica_domain(model) for model in models]
```
